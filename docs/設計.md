# ROtxt 設計文件（v1）

> 文字版 RO 仙境傳說。掛機練等、打寶、轉職。CLI 客戶端 + 伺服器，之後接網頁。
> 本文件是 2026-09-06 grill 對話的結論固化。開始寫程式前以此為準，改動要回頭更新這份。

參考來源：
- ludens.com.tw/ro-pocket（口袋戰記攻略庫：卡片 / MVP / 怪物出沒 / 世界觀）
- ro.ntome.com（仙境全書：副本清單與冷卻、三轉轉職副本）
- 經典 Pre-Renewal RO 資料庫（怪物數值 / 職業技能）

---

## 1. 核心定位

- 類型：文字掛機 RPG，多人同伺服器但 v1 各玩各的（可交易、可聊天、有排行榜）。
- 玩法主軸：**掛機打怪 → 練雙等級 → 打寶（裝備 / 卡片）→ 精煉養裝 → 轉職**。
- 還原原則：**數值與結果高還原，模擬過程可抽象**。每個「為省資源而抽象」的點都要記進 `docs/抽象清單.md` 並經確認。

---

## 2. 架構

```
客戶端 (rich TUI, Python)  ──REST──▶  伺服器 (FastAPI + uvicorn)
                                          │
                                          ├─ 遊戲引擎 (shared/ 資料模型 + server/ 邏輯)
                                          └─ SQLite (WAL 模式)
```

- **client-server 從第一版就是。** 所有遊戲狀態在伺服器端，客戶端只送「意圖」、顯示結果。
- **惰性結算**：伺服器不跑全域 tick。每個角色存「掛機起始時間戳 + 地點 + 設定」，客戶端請求狀態時，伺服器當下結算「上次結算到現在」這段、寫 DB、回傳事件。
- **在線即時感**：客戶端每 3~5 秒 poll 一次，每次結算一小段，滾動顯示。關掉客戶端角色照樣在掛（時間戳繼續走）。
- WebSocket、全域 tick 留給網頁版或 v2。

### monorepo 目錄

| 目錄 | 內容 |
|---|---|
| `server/` | FastAPI 應用、遊戲引擎邏輯、結算器、DB 存取 |
| `client/` | rich TUI 客戶端 |
| `shared/` | pydantic 資料模型（怪物、技能、裝備、角色…），server/client 共用 |
| `data/` | 結構化遊戲資料檔（怪物表、地圖表、掉落表、技能表、裝備表、卡片表） |
| `docs/` | 本文件、抽象清單、資料 schema、ADR |

## 3. 技術棧

- 伺服器：FastAPI + uvicorn
- DB：SQLite，WAL 模式（多人同時寫不卡）
- 密碼：passlib + bcrypt
- 資料模型：pydantic（`shared/`）
- 客戶端 TUI：rich
- 部署：Docker 容器 → J1900，走現有反向代理 + HTTPS
- 測試：pytest（戰鬥公式、結算邏輯必須有單元測試）
- 每次程式實作後跑 `/codex-review` 到 LGTM 才算完成

## 4. 帳號與角色

- **邀請碼制**：手動產生數組邀請碼發給朋友。首次連線輸入邀請碼 + 自訂帳號名 + 密碼，綁成一個帳號。
- **一帳號最多 3 隻角色。** 限制在帳號層，不用 IP。
- IP 只當輔助紀錄（登入來源、防洗邀請碼），不作身分。
- **帳號倉庫共用**（3 隻角色共用），角色背包各自獨立。
- 存檔：伺服器端 SQLite。帳號 / 角色 / 背包 / 掉落紀錄 / 精煉紀錄 分表。定時 cron 備份 DB 檔到別處。

## 6. 角色養成

### 6.1 雙等級（Pre-Renewal 制）

- **Base Level**：升級給屬性點，玩家手動分配 STR / AGI / VIT / INT / DEX / LUK。屬性點公式照經典（低級 1 點、高級遞增）。
- **Job Level**：升級給技能點，玩家手動點技能樹。
- 掛機兩種經驗一起漲。轉職門檻看 Job Level。
- v1 Base 上限 **50**，但經驗曲線照「未來延伸到 99+」的公式鋪，v2 拉上限只是解鎖不重調。

### 6.2 職業樹（傳統 RO，v1 到二轉）

```
新手 ──▶ 劍士 ──▶ 騎士 / 十字軍
      ├▶ 法師 ──▶ 巫師 / 賢者
      ├▶ 弓箭手 ─▶ 獵人 / 詩人吟遊
      ├▶ 服事 ──▶ 牧師 / 武僧
      ├▶ 商人 ──▶ 鐵匠 / 鍊金術師
      └▶ 盜賊 ──▶ 刺客 / 流氓
```

- 新手期壓短：照 ludens 開場主線做教學關（協會考核 → 東門村郊清瘋兔 → 奶奶委託獵野豬 → 學鑑定 → 打天使波利 → 梅林引介卡片系統）。
- Job 10 觸發一轉任務（六選一）。
- 二轉：達 Job Level 門檻 + 跑轉職任務。
- 三轉（含 ntome 那些轉職副本：獵靈士 / 盧恩龍爵…）留 v2。
- 每職 **4~6 個代表技能**，不搬整棵 RO 技能樹。
  - 例：劍士 = 二刀連擊 / 爆裂波動 / 增益(怒殺劍氣) / 衝撞 / 被動(HP 回復力提升)

### 6.3 技能掛機使用

- **玩家設技能優先序**：每個主動技能三個設定 = 開 / 關、觸發條件（每回合 / 血低於 X% / 敵方多於 N 隻 / CD 好就放）、順位。
- 掛機結算按這個跑。系統預設先配好一套堪用的。
- 被動技能永遠生效。

### 6.4 洗點

- v1 開發期免費洗點（方便測）。
- 正式版：洗點吃 Zeny。

## 7. 戰鬥

- **回合制模擬**，Pre-Renewal 公式骨架。
- 一般雜怪掛機：批次快轉，只回報統計（擊殺數、掉落、經驗、時間）。
- MVP 王戰：逐回合演，顯示「第 N 回合，X 對你造成 Y 傷害，你剩 Z 血」。
- v1 做**物理 + 魔法**傷害。**屬性相剋（火水風地聖闇…）留 v1.5。**
  - MATK 進 v1 是底線不是取捨：法師整條線（法師→巫師/賢者）與服事補術吃 INT、放魔法，
    沒有 MATK 這些職業的加點與技能無法運作。v1 六職都要完整。
  - v1 魔法一律打「中性屬性」傷害。v1.5 加相剋表時是在魔法傷害後插一層倍率查詢（加東西非改東西）。
- 戰鬥屬性：HP、SP、ATK、MATK、DEF、MDEF、HIT、FLEE、ASPD、暴擊。
- Pre-Renewal 傷害骨架（實際係數建置時查表校準）：
  - 物理傷害 ≈ (ATK - 目標 DEF百分比減傷) 再扣目標 VIT 軟防
  - 魔法傷害 ≈ (MATK - 目標硬 MDEF 平減) 再扣 INT/等級來的軟 MDEF；MATK 主要吃 INT
  - 命中：攻方 HIT vs 守方 FLEE，二元判定命中率 = 80% + (HIT - FLEE)（魔法必中，不判 FLEE）
  - ASPD → 每回合攻擊次數 / 傷害係數（見抽象清單第 1 項）

### 已知抽象點（詳見 `docs/抽象清單.md`）

1. **ASPD 不做逐刀即時模擬**：回合制批次結算下，高 ASPD 轉成「每回合多段傷害」或「單位時間傷害係數」。刺客高 ASPD = 傷害係數高，DPS 數值與還原後一致，不畫每一刀。

## 8. 掛機機制

- **即時 + 離線都做。**
- 在線（客戶端開著）：每 3~5 秒 poll，逐次擲骰、逐行播報。
- 離線：混合結算
  - 經驗、金錢：統計式一次算（穩定可預期）
  - 稀有掉落（卡片、稀有裝）：擲骰 + 保底計數器（保留賭博感）
  - 在線 / 離線兩邊期望值必須校準對齊
- **離線效率 60%**（設定檔可調）
- **離線累積上限 8 小時**（設定檔可調）
- **掛機安全網**：雜怪打不過 → 自動撤退並停止結算，不會死。上線看到「你在戈壁撐不住，已於 2 小時前撤退，實際掛機 2 小時」。
- 補品：設定「血低於 X% 自動嗑 Y 補品」，補品用完走安全網撤退。

## 9. 打寶

### 9.1 裝備

- 孔位：武器、副手、頭上、鎧甲、肩披、鞋子、飾品 ×2
- 稀有度分級：普通 / 精良 / 傳說（掉落播報用）
- 怪物有掉落表（裝備、材料、Zeny、卡片）

### 9.2 卡片

- 每種怪對應一張自己的卡，低機率掉落。
- 卡片插進裝備孔給效果，效果做**結構化資料**（不是純文字）。
- 掉率做**設定檔可調**（RO 原版 0.01~0.1% 太痛，v1 拉高並可調），配保底計數器。

### 9.3 精煉（v1 就要）

- +1~+4 安全，+5 以上會失敗。
- 失敗**降級**（不直接打碎）。「失敗即碎」列為之後可選的硬核模式。
- 吃材料（打怪掉的精煉礦）+ Zeny。
- 精煉上限 +10。

### 9.4 圖鑑收集加成

- 留 v1.5（跟屬性系統一起）。

## 11. MVP 王

- **冷卻挑戰制**：每隻 MVP 有個人冷卻（低等 6~12 小時、高等 1 天，參考 ntome 冷卻邏輯）。
- 冷卻好 → 發起挑戰 → 逐回合王戰。
- 贏：豐厚掉落（MVP 卡、稀有裝）。輸：扣經驗（約 1~2%）+ 進冷卻。
- **可中途逃**：王回滿血、進短冷卻、不扣經驗。

---

## 12. 死亡懲罰

- 掛機雜怪：**永遠不會真的死**，血見底自動撤退 + 停止結算。
- 主動挑 MVP：死亡扣約 1~2% 當前等級經驗。

## 13. 多人與社交（v1）

- **純平行單人 + 社交層**，不做 PvP、不做組隊。
- v1 有：
  - **排行榜**（等級 / 卡片數 / 精煉…）
  - **交易**：面對面，雙方各自把東西放上桌、兩邊按確認才成交。原子交易，防送錯與卡 bug。
  - **世界頻道聊天** + 伺服器公告
  - **公會**：建會 / 入會 / 會員列表 / 公會聊天。純社交殼，先不做公會技能 / 公會副本。
- v2：組隊副本、公會副本、公會 buff、系統寄賣交易所。

## 15. 資料 schema（骨架，細節見 `docs/資料schema.md`）

**設計原則：schema 一開始就照最終還原度設計，v1 只是填的 row 少，不是欄位缺。**

- `monster`：id、名稱、Base/Job 經驗、HP、SP、ATK、MATK、DEF、MDEF、HIT、FLEE、ASPD、**屬性**、**種族**、**體型**、掉落表、是否 MVP、MVP 機制欄位、出沒地圖
- `map`：id、名稱、所屬城鎮系、等級帶、怪群、MVP、解鎖條件
- `job`：id、名稱、上一階、轉職門檻、成長係數（HP/SP/各屬性）、技能列表
- `skill`：id、名稱、職業、類型（主動/被動）、SP 消耗、CD、效果（結構化）、掛機觸發預設
- `equipment`：id、名稱、孔位、稀有度、基礎屬性、可精煉、卡片孔數
- `card`：id、名稱、對應怪物、掉率、插入孔位、效果（結構化）
- `item`：消耗品 / 材料（補品、精煉礦、傳送翼…）

### 資料管線

- v1 開發時實際爬 ludens + ntome + 經典 RO wiki，把 v1 要用的那批（怪 12~16 / 圖 8 / MVP 4~6 / 裝備 ~40 / 卡 16 / 技能 30）整理成 `data/` 下的結構化檔。
- 建成可重用管線，v2 擴充沿用同一管線、同一 schema，**只加 row 不改既有值**。
- 術語從一開始鎖 ludens/ntome 繁中用詞。

## 17. 開發階段拆解（草案，寫 plan 時細化）

1. **地基**：repo 骨架、shared/ pydantic 模型、SQLite schema + WAL、FastAPI 起服務、邀請碼 / 帳號 / 登入、角色 CRUD（3 角色限制）

4. **掛機結算器**：在線逐次擲骰 + 離線混合結算、期望值校準測試、安全網、自動補品
5. **養成**：雙等級 / 加點 / 技能樹 / 轉職任務（新手 → 一轉 → 二轉）
6. **打寶**：掉落表、裝備穿脫、卡片、精煉
7. **經濟**：Zeny、NPC 商店、賣寶、倉庫
8. **MVP**：冷卻挑戰、王戰、掉落
9. **社交**：排行榜、交易、聊天、公會殼
10. **客戶端**：rich TUI 面板、指令、選單、poll 迴圈
11. **部署**：Dockerfile、J1900 容器、反向代理、DB 備份 cron
12. 每階段結束跑 `/codex-review`
