# 技能全補計畫（對照原版一二轉）

目標：把技能表補到接近原版 RO（pre-renewal）一轉 + 二轉的完整度。
策略 A：掛機下沒意義的技能照補，用近似效果，技能樹 100% 對得上原版。

## 引擎現有效果詞彙（新技能只能用這些，或先擴充引擎）

| type | 欄位 | 語意 |
|------|------|------|
| `physical_hit` | `power_pct[]`, `element?`, `hits?`, `debuff?` | 單體物理，可帶屬性 / 多段 / 附加 debuff |
| `magic_hit` | `power_pct[]`, `element`, `hits?` | 單體魔法 |
| `aoe` | `element`, `power_pct[]` | 範圍魔法傷害 |
| `heal_hp` | `matk_pct[]` | 補血（自己） |
| `buff` | `stats{}`, `duration_s` | 自我增益（多屬性） |
| `debuff` | `stat`, `pct[]`, `duration_s` | 對敵減益（單屬性） |
| `passive_stat` | `stat`, `amount[]` | 被動固定加值 |
| `proc` | `event`, `chance_pct[]`, `effect` | 觸發型（目前只認 `on_attack` → `extra_hit`） |

掛機觸發（`idle_default.trigger`）：`passive` / `every_turn` / `cooldown_ready` / `sp_available` / `hp_below_50` / `hp_below_30`

### 近似對應規則（本計畫共用）

- **陷阱** → `aoe`（帶屬性）+ `cooldown_s` 拉長（模擬佈置後引爆）
- **牆 / 結界（安全結界、Pneuma、能量外套）** → `buff` 加 `defense` / `mdef`，`sp_available` 觸發
- **隊友 buff（掛機沒隊友）** → 一律改成自我 `buff`
- **純功能（擺攤、偷竊、鍛造、製箭、傳送、鑑定）** → `passive_stat` 給小幅相關加值，或純擺著（`passive`、amount 全 0），技能樹點得下去即可
- **狀態異常（睡、盲、凍、石化）** → 目前引擎沒有硬控，一律降級成 `debuff`（flee / aspd / hit / defense 擇一），`duration_s` 短
- **驅散 / 解毒 / 狀態恢復** → 自我 `heal_hp`（小量）+ 標記，實際解 debuff 待引擎支援

### 待引擎擴充（不擋本計畫，先用近似；有餘力再做）

1. `debuff` 支援多屬性（現在只吃單 stat）
2. `proc` 支援 `on_hit_taken`（反擊類：反擊、毒素反應、Kyrie 擋招）
3. 真狀態異常（凍結 / 睡眠 / 石化 = 跳過回合）
4. DoT（持續傷害：毒、Magnus、Sanctuary 反傷）

## 批次順序（合併版）

| 批 | 內容 | 約略技能數 | Codex |
|----|------|-----------|-------|
| B1 | 本文件 + `scripts/check_skills.py` 驗證器 + 接測試 | 0 | 免（驗證器自審） |
| B2 | 一轉近戰組：novice + swordman + thief + merchant + archer（含 auto_berserk、charge_arrow 搬家） | ~15 | **審**（搬家動 jobs.json） |
| B3 | 一轉施法組：mage + acolyte | ~16 | 免（純加資料，驗證器擋） |
| B4 | knight + assassin（含 shield_charge 改名 counter_attack、katar_mastery 改中文名） | ~10 | **審**（改名 + proc 近似） |
| B5 | wizard + blacksmith（含 frost_armor 改名 frost_nova） | ~15 | **審**（改名 + 若動引擎） |
| B6 | priest | ~11 | 視情況（sanctuary 走 every_turn HoT、resurrection 大補，若要動引擎才審） |
| B7 | hunter（非陷阱 + 全陷阱線，內部可分 2 個子代理） | ~13 | **審**（陷阱近似最多、最容易踩 schema） |
| B8 | 平衡校正：新戰力 vs 怪物 HP / 經驗曲線 | 0 | **審** |

一轉六職的 `test_each_first_job_has_five_skills`（tests/test_data_files_valid.py:72）會在 B2/B3 失效，該批順手改成「>= 5 且與 skills.json 一致」，或直接刪掉讓 `check_skills.py` 的第 11 項接手。

每批流程：加技能 → 設掛機預設（trigger/priority/enabled）→ 跑 `check_skills.py` → 加 2~3 個戰鬥或載入測試 → 本地相關測試 → （高風險批才）Codex → commit → 回報等確認再進下一批。

## 風險

- 補完後每職戰力大幅上升，B13 平衡校正必做。
- 近似效果讓部分技能實質是「+小數值」或純裝飾，跟原版手感有落差，但符合策略 A 的取捨。
- 搬家 / 改名的技能（auto_berserk、shield_charge、charge_arrow、frost_armor、katar_mastery）會動到 jobs.json 與既有角色已學資料；正式庫角色少，直接改，必要時寫一次性 migration 清掉孤兒 skill id。
