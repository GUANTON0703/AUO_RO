## 設計決策

1. **可堆疊 vs 實例化**：
   - `character_items(character_id, item_id, qty)` 主鍵 `(character_id, item_id)`。`item_id` 涵蓋 `data/items.json`（材料/消耗品）與 `data/cards.json`（背包裡的卡按卡 id 堆疊）。
   - `character_equipment(id, character_id, equipment_id, refine, equipped_slot, card_ids, acquired_at)`。每件裝備一列，有自己的精煉值（0~10）、鑲的卡（JSON list）、以及是否裝備中（`equipped_slot` 有值 = 裝在該部位）。
2. **掉落入袋**：掛機結算的 `drops` dict，item_id 若在 `content.equipment` → 建一列 `character_equipment`（refine 0，未裝備）；否則 upsert `character_items` 加數量。每次 `status`/`stop` 結算就寫，不再留 `hunt_loot` staging（`hunt_loot` 欄位改當「本次登入以來的累計」給客戶端顯示，不是待領清單）。
3. **裝備欄位**：phase 5 的 `equipped_items` JSON 欄位**廢棄**，改用 `character_equipment.equipped_slot`。一個部位同時只能一件。
4. **卡片鑲嵌**：從 `character_items` 扣一張卡 → 加進某件裝備的 `card_ids`（該裝備要有空孔）。**不可拆卡**（v1；拆卡道具列 v1.5）。
5. **精煉**：
   - `refine_bonus_per_level`：`{"atk":2,"matk":2,"def":1,"mdef":1,"max_hp":15,"flee":1,"hit":1,"crit":1}`。裝備每 +1，其 stats 裡有的鍵各加對應值。
   - 成功率（從 refine N 衝到 N+1）：`{0:1.0,1:1.0,2:1.0,3:1.0,4:0.6,5:0.4,6:0.4,7:0.25,8:0.2,9:0.1}`。+10 封頂。
   - **失敗 → 降 1 級**（`refine -= 1`，不會低於 0），材料照樣消耗。
   - 材料：武器吃 1 `oridecon`、防具/其他吃 1 `elunium`。Zeny 成本 `(refine + 1) * 200`。
6. **補品接掛機**：`hunt/status` 結算前，讀角色 `character_items` 裡 `kind == "consumable"` 且 effects 有 `heal_hp` 的道具，挑回血量最大的一種當掛機補品，把 `qty` 跟 `heal` 帶進 `settle`。結算後扣掉 `result.potions_used`。
7. **卡片效果**：`build_player_combatant` 已處理 `flat_stat` / `percent_stat`。`element_resist` / `race_damage` / proc 型戰鬥引擎 v1 仍不支援——照舊略過（記進抽象清單）。

```python
import random

REFINE_CAP = 10
_RATE = {0: 1.0, 1: 1.0, 2: 1.0, 3: 1.0, 4: 0.6, 5: 0.4,
         6: 0.4, 7: 0.25, 8: 0.2, 9: 0.1}
_ARMOR_SLOTS = {"armor", "shoes", "head", "garment", "offhand", "accessory"}


def success_rate(current_refine: int) -> float:
    if current_refine >= REFINE_CAP:
        return 0.0
    return _RATE.get(current_refine, 0.1)


def refine_ore_for(slot: str) -> str:
    return "oridecon" if slot == "weapon" else "elunium"


def refine_zeny_cost(current_refine: int) -> int:
    return (current_refine + 1) * 200


def attempt_refine(current_refine: int, rng: random.Random) -> tuple[int, bool]:
    if current_refine >= REFINE_CAP:
        return current_refine, False
    if rng.random() < success_rate(current_refine):
        return current_refine + 1, True
    return max(0, current_refine - 1), False


REFINE_BONUS_PER_LEVEL = {"atk": 2, "matk": 2, "def": 1, "mdef": 1,
                          "max_hp": 15, "flee": 1, "hit": 1, "crit": 1}


def refine_stat_bonus(base_stats: dict, refine: int) -> dict:
    return {k: REFINE_BONUS_PER_LEVEL.get(k, 0) * refine
            for k in base_stats if k in REFINE_BONUS_PER_LEVEL}
```

## Task 4: 背包 / 裝備 / 鑲嵌 / 精煉 API

**Files:** Create `server/api/inventory.py`; Modify `server/app.py`; Test `tests/test_api_inventory.py`

端點（都在 `/api/characters/{id}` 下，需 auth 且角色屬該帳號）：
- `GET /inventory` → `{items: {...}, equipment: [{id, equipment_id, refine, equipped_slot, card_ids}]}`
- `POST /inventory/equip` body `{equipment_instance_id}` → 驗證 slot 該裝備定義的 slot、job_ids（空=全職）、required_level ≤ base_level；同 slot 已有的先卸下；設 `equipped_slot`
- `POST /inventory/unequip` body `{slot}` → 清該 slot
- `POST /inventory/socket` body `{equipment_instance_id, card_item_id}` → 卡在背包有、裝備有空孔（`len(card_ids) < equipment.card_slots`）、卡的 slot 符合裝備 slot；扣卡、加進 card_ids
- `POST /inventory/refine` body `{equipment_instance_id}` → 讀 refine、算 ore + zeny、背包有 ore、角色有 zeny；扣掉、`attempt_refine`、寫回新 refine；回 `{success, refine, message}`
