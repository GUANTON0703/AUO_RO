# 社交 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development。
> **審核政策**：不跑 codex。分批做完跑 `uv run pytest -q` + 掃 diff；階段收尾一次自行審核。

**Goal:** 讓朋友在同一個伺服器有「一起玩」的感覺——排行榜看誰強、面對面交易換東西、世界頻道嘴砲、公會建會入會。不做 PvP、不做組隊。

**Architecture:** 排行榜是查詢（無新表）。交易用「雙方各自放上桌、都按確認才成交」的狀態機（`trades` 表）。聊天用 `chat_messages` 表 + 輪詢。公會用 `guilds` / `guild_members` 表。全部走 REST + client 輪詢，不做 WebSocket。

**Tech Stack:** 沿用。

## 設計決策

1. **排行榜**：`GET /api/leaderboard?by=base_level|job_level|zeny|cards|refine`。回前 50 名（角色名、帳號、值）。`cards` = 該角色蒐集到的不同卡片數；`refine` = 最高精煉值。純 SQL 查 characters + character_items + character_equipment。
2. **交易**（面對面、原子）：
   - `POST /api/trade/offer` body `{to_username}` → 建一筆 `trades`（status `open`），回 trade_id
   - `POST /api/trade/{id}/put` body `{item_id, qty}` 或 `{equipment_instance_id}` → 把自己的東西放上桌（記在 `trade_items`，暫時不從背包扣，成交才扣）
   - `POST /api/trade/{id}/confirm` → 該方確認。雙方都 confirm 且雙方桌上物品都還在背包 → **原子執行**：兩邊物品互換 + status `done`
   - `POST /api/trade/{id}/cancel` → 取消
   - `GET /api/trade/pending` → 別人開給我、還沒結束的交易
   - 任一方改動桌上物品 → 對方的 confirm 作廢（防抽換）
3. **聊天**：`chat_messages(id, channel, account_id, character_name, text, created_at)`。channel = `world` 或 `guild:<id>`。`POST /api/chat` body `{channel, text}`（text ≤ 200）。`GET /api/chat?channel=world&after=<id>` 回 after 之後的訊息（≤ 100 筆）。伺服器公告用 `channel=world`、`character_name=系統`。
4. **公會**（純社交殼，無公會技能/副本）：
   - `guilds(id, name UNIQUE, leader_account_id, created_at)`、`guild_members(guild_id, account_id, character_name, role, joined_at)`（role: leader / member）
   - `POST /api/guild` body `{name}` → 建會（建者是 leader），一帳號只能在一個公會
   - `POST /api/guild/{id}/join` → 直接加入（v1 無審核）
   - `POST /api/guild/leave` → 退會（leader 退會 → 若還有人，最早加入的接任；沒人 → 解散）
   - `GET /api/guild/mine` → 我的公會 + 成員列表
   - `GET /api/guild` → 所有公會 + 人數
5. **一帳號一角色**（跟前面一致，交易/聊天/公會都用帳號第一隻角色的名字顯示）。
6. **輪詢**：client 在「主畫面閒置」時不自動撈聊天（避免洗版）；`chat` 指令進聊天模式（每 3 秒撈 world + guild，輸入送出，按 Enter 空行離開）。
