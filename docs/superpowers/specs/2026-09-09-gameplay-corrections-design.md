# 技能重置、精煉、插卡與 MVP 難度修正設計

## 目標

修正四個玩家已實際遇到的行為：二轉角色洗技能後無法重點新手／一轉技能、隨機精煉不會失敗、鑲卡選單顯示不相容卡片，以及 MVP 幾乎打不中玩家且完全不會施放技能。

## 已確認規則

### 1. 洗技能後可重點完整職業鏈

- 可學技能的職業範圍是目前職業的完整祖先鏈。例如騎士可學新手、劍士、騎士技能；刺客可學新手、盜賊、刺客技能。
- 技能前置、最高等級與可用技能點仍照現有規則驗證，不因前職技能而放寬。
- 洗技能只清空已學技能；轉職時累積的技能點保留，因此玩家可從新手技能開始重新分配。
- 前端所有祖先職業技能都顯示加點按鈕；只有滿級、前置未達或技能點不足的技能不可送出。
- 後端以 `job_ancestry(current_job)` 判斷技能是否屬於可學職業鏈，避免只修畫面卻仍被 API 擋住。

### 2. 隨機精煉改為兩階段判定

- 普通精煉維持現有材料、Zeny、成功率與失敗降一級規則。
- 隨機精煉消耗一份相同礦石，Zeny 費用為同精煉等級普通模式的 10 倍。
- 隨機精煉先使用與普通模式完全相同的成功率判定：
  - 判定失敗：不抽隨機增量，精煉等級下降 1，最低為 +0。
  - 判定成功：再抽增量 `+0 / +1 / +2 / +3`，機率維持 `10% / 50% / 35% / 5%`，最高不超過 +10。
- 成功判定通過但抽到 `+0` 時，API 回報成功、增量為 0，訊息明確說明「判定成功但增量 +0」，避免誤認為程式沒有作用。
- API 回應保留 `mode`、`success`、`increment` 與最終 `refine`，讓前端能分辨「失敗降級」和「成功但 +0」。

### 3. 鑲卡只顯示相容部位

- 玩家從某件裝備按下鑲卡時，選卡清單只列 `card.slot == equipment.slot` 的背包卡片。
- 選單同時顯示卡片可插部位，讓玩家在確認前看得懂相容原因。
- 沒有卡槽、卡槽已滿的裝備不顯示鑲卡按鈕。
- 有空槽但背包沒有相容卡片時，直接顯示該裝備需要的部位，不顯示其他卡片。
- 後端既有的部位、卡槽與持有數量驗證保留，作為最終權威。

### 4. MVP 具備可靠威脅與可見技能

- 不修改一般怪物命中規則；只對 `is_mvp` 的戰鬥角色套用 Boss 戰鬥設定。
- MVP 的物理普攻與物理技能最低命中率為 35%。玩家的高 FLEE 仍可降低原本命中率，但不能再把王壓到長期 5% 命中。
- 所有 MVP 由共用工廠取得一組基礎技能，不逐隻複製相同 JSON：
  - `王者重擊`：160% 物理傷害，2 回合冷卻。
  - `元素爆發`：140% 魔法傷害，使用該 MVP 自身屬性，4 回合冷卻；魔法傷害不受 FLEE 閃避。
  - `狂暴`：HP 低於 50% 時施放一次，持續 5 回合並提高 ATK 與 HIT 25%。
- MVP 建立戰鬥角色時取得足夠施放整場 30–80 回合戰鬥的 SP；一般怪物維持目前 0 SP／無技能行為。
- 技能沿用既有 `ResolvedSkill`、`cast_skill` 與 `SkillEvent`，前端可直接顯示技能名稱與傷害，不新增另一套戰鬥事件格式。
- 平衡驗收以多個固定亂數種子測試：高 FLEE 角色仍會受傷；每隻 MVP 都會產生技能事件；同級合理裝備角色不再能穩定無傷通關。這次不新增逐隻專屬技能或新階段機制。

## 實作邊界

- 技能：`server/progression/skills.py`、`server/api/progression.py`、`web/js/screen-build.js` 與對應測試。
- 精煉：`server/loot/refine.py`、`server/api/inventory.py`、`web/js/screen-bag.js` 與對應測試。
- 鑲卡：`web/js/screen-bag.js` 與前端測試；後端只在測試確認既有防線，不改資料庫格式。
- MVP：新增集中式 Boss 技能建立邏輯，並調整 `Combatant`／命中共用點、`challenge_mvp` 與戰鬥測試；不改一般怪物資料。

## 測試策略

依 TDD 逐項建立失敗測試後才修改正式程式：

1. 二轉角色洗技能後，可依序學新手、一轉、二轉技能；旁系職業技能仍被拒絕。
2. 隨機精煉第一個亂數控制成功／失敗，只有成功才消耗第二個亂數抽增量；驗證失敗降級、成功 +0、+10 封頂與 10 倍 Zeny。
3. 前端以裝備部位過濾卡片，無空槽不顯示按鈕；API 仍拒絕不相容卡片。
4. 高 FLEE 玩家對 MVP 的固定亂數戰鬥不再呈現近乎全 miss；每隻 MVP 至少能產生一個 `SkillEvent`，一般怪物仍沒有自動取得 Boss 技能。
5. 完成 focused tests、全部 Python tests、Node 前端 tests 與內容驗證，再執行獨立 Claude Code diff 審核。

## 非目標

- 不為每隻 MVP 設計獨立技能名稱、召喚物或多階段機制。
- 不調整一般怪物、玩家 PVP 或全域命中公式。
- 不修改普通精煉價格、礦石數量或隨機增量權重。
- 不更動既有角色裝備、技能或資料庫紀錄。

## 驗收標準

- 洗技能後，二轉角色能重新學完整職業鏈技能，且不能跨到其他職系。
- 隨機精煉會依普通成功率失敗；成功後才套用既有增量分布，費用正確為 10 倍。
- 鑲卡介面只顯示目標裝備可使用的卡片及正確部位。
- 所有 MVP 會施放可見技能；高 FLEE 不能再讓 MVP 長期只有 5% 命中，且合理同級角色會承受實質傷害。
- 所有自動測試通過，獨立審核沒有 Critical／High 問題。
