# Boss、掉落、技能、精煉與狀態頁改版設計

## 目標

改善 Boss 挑戰的難度與打擊感，讓 GM 能調整裝備／卡片掉落率，重整技能分階段顯示，新增雙模式精煉，修正掛機狀態同步，並在 Base／Job 經驗條顯示百分比。

## 已確認需求

1. Boss 難度提高攻擊、防禦、血量，並增加 Boss 數量；同級畢業裝玩家的目標擊殺時間約 30–80 回合，且有死亡／撤退風險。
2. 手動 MVP 戰與掛機遇到 Boss 都逐回合播放；離線大批次結算仍快速完成。
3. 掉落率支援全域值與來源專屬值。來源專屬值優先，否則使用全域值；GM 可調整並即時生效。
4. 技能顯示新手／一轉／二轉三個階段，分區折疊；所有技能可查看。未滿足前置條件時暗紅並禁止加點。
5. 精煉分普通與隨機。隨機精煉以目前等級為基準增加 +0／+1／+2／+3，機率為 10%／50%／35%／5%，最高 +10；普通精煉規則維持現行行為。
6. 修正狀態頁載入偏慢，以及掛機顯示交戰中但沒有戰鬥訊息的同步問題。
7. Base Lv 與 Job Lv 都顯示當前等級內經驗百分比，並保留目前／下一級經驗值。

## 設計

### 1. Boss 與戰鬥播放

- 延續現有 `role="boss"`、MVP 資料格式與 `simulate_fight`，集中調整 Boss 的統一倍率與個別 Boss 數值。
- 擴充中後期地圖的 MVP 資料，新增完整卡片與必要掉落引用，保持 content loader 的引用完整性。
- 新增／擴充驗證腳本，以各職業同級畢業裝跑 Boss，檢查回合數、勝負與是否出現無法擊殺或秒殺。
- 後端事件格式維持可序列化的逐回合 events；前端建立播放佇列：即時戰鬥逐回合播放，Boss 採較慢且有下限的節奏，離線批次與大量歷史事件仍直接顯示結果。
- 播放狀態與結算狀態分離，避免因前端播放尚未完成而誤判伺服器仍在戰鬥。

### 2. 掉落率與 GM

- 新增可持久化的全域掉落覆寫設定，以及 `(source_id, item_id)` 來源專屬覆寫設定。
- 掉落計算統一透過解析器取得有效機率：來源專屬值 → 全域值 → content 原始值。
- 一般怪物、MVP、裝備與卡片都使用同一套解析流程；不改變既有 pity、數量與離線結算邏輯。
- GM API 提供讀取與更新設定，輸入限制為 0–1；GM 面板可依來源搜尋裝備／卡片並顯示目前有效值。
- 更新後立即作用於下一次掉落，不修改既有角色背包。

### 3. 技能分階段顯示

- 使用 jobs 的 `tier` 與技能的 `job_id` 組織新手／一轉／二轉區塊，不重複建立另一份技能資料。
- 各區塊可展開／收合，預設保留目前職業階段展開。
- 前端計算並顯示 `requires` 的技能名稱與需求等級；需求未達時套用暗紅樣式並停用加點按鈕。
- 後端現有 `can_learn` 仍是最終權威，前端狀態只負責即時提示，不放寬既有職業、等級與技能點驗證。

### 4. 雙模式精煉

- `POST /inventory/refine` 增加模式欄位，預設 `normal` 以維持舊客戶相容性。
- `normal` 使用現有成功率／失敗降級流程。
- `random` 先扣除同一精煉材料與 Zeny，依固定權重抽取增量 0、1、2、3；結果以 `min(10, current + increment)` 寫回。
- 精煉介面在同一操作入口讓玩家選擇普通或隨機，回應明確顯示模式、抽中增量與結果。
- 隨機機率抽樣邏輯放在 `server/loot/refine.py`，以可注入 RNG 測試，避免 API 測試依賴真隨機。

### 5. 狀態頁與掛機同步

- 先以 API／結算單元測試重現慢請求、暖啟動、無時間推進與事件重複／遺失情境，再修改。
- `/hunt/status` 回應增加明確的戰鬥／結算狀態與事件批次語意；不以「有 hunting id」單獨代表正在交戰。
- 前端初始化合併可安全合併的角色／狀態讀取，避免重複請求；輪詢期間只更新數值與新增事件。
- 事件批次使用穩定游標／批次識別，重複輪詢不重播，頁面切換不把尚未消費的事件誤當空事件。
- 只有收到實際戰鬥事件或伺服器明確回報 combat 狀態時才顯示「交戰中」。

### 6. 經驗百分比

- 使用既有 server progression level curve 的同等公式在前端計算百分比，避免新增資料庫欄位。
- Base 與 Job 都顯示 `目前經驗 / 下一級需求（百分比）`，進度條與文字共用同一計算結果。
- 處理滿級、需求為零、升級瞬間與跨階段 Job curve 的邊界值，百分比限制在 0–100%。

## Agent 分工與整合邊界

1. Boss／MVP：`data/mvps.json`、必要卡片／掉落資料、Boss scaling、MVP／戰鬥測試。
2. 掉落／GM：server settings schema、drop resolver、GM API／面板、掉落測試。
3. 技能：`web/js/screen-build.js` 與樣式、技能 UI 測試／既有 API 回歸。
4. 精煉：`server/loot/refine.py`、inventory API、`web/js/screen-bag.js` 與測試。
5. 狀態／播放：`server/api/hunt.py`、settlement event plumbing、`web/js/app.js`／`web/js/screens.js` 與測試。
6. 經驗：狀態／角色頁經驗呈現與前端回歸測試。

共享邊界：Boss agent 負責戰鬥事件資料語意；狀態 agent 只修改事件傳輸與播放，不改 Boss 平衡。掉落 agent 負責掉落解析；Boss agent 只提供資料，不直接改 GM 規則。若同一檔案不可避免重疊，依序整合並在合併後跑完整測試。

## 驗收標準

- content check 與全套 Python 測試通過。
- 同級畢業裝 Boss 模擬落在 30–80 回合目標區間，且弱角色可合理失敗／撤退。
- 手動 MVP 與即時掛機 Boss 的戰鬥事件逐回合可見，不在數秒內壓縮播放 30 回合；離線大批次不被拖慢。
- GM 可調整全域與來源專屬裝備／卡片機率，且優先順序可測試驗證。
- 技能分階段、暗紅鎖定與既有前置驗證一致。
- 普通精煉舊行為不回歸；隨機精煉權重與 +10 封頂可由測試驗證。
- 狀態頁無戰鬥事件時不顯示交戰中，且重複輪詢不重播或遺失事件。
- Base／Job 等級經驗皆顯示正確百分比。
