# 資料來源與擴充流程

## 關鍵決策（2026-09-06 資料管線階段確立）

1. **名冊權威 = ludens（`guide.ludens.com.tw/ro-pocket`）。** 怪物 / MVP / 卡片的名字、等級、種族、屬性、體型、出沒地圖、地圖結構一律照 ludens 的繁中用詞。
2. **戰鬥數值 = 等級基準公式產生。** 兩個參考站都沒公布怪物 HP/ATK/DEF。用 `server/content/monster_stats.py` 的 `baseline(level, role)` 依等級算基準值，乘角色定位係數（glass/normal/tank/boss），校準成早期怪接近 Pre-Renewal 手感（Lv1 波利級 HP≈50、ATK≈7~10）。**產出的最終數值寫死進 `data/monsters.json` / `data/mvps.json`，之後不對就直接改該筆，不改公式。**
3. **卡片效果 = 經典 RO 風格獨特效果**，不採口袋版的純數值棒。schema 把效果做成結構化清單，`flat_stat` 是其中一種型別，特殊效果（proc、resist、race_damage）是其他型別。
4. **技能 / 掉落的 effects 目前未型別化**（`list[dict]`），戰鬥引擎階段才加 discriminated union 並回頭驗證。
5. **屬性相剋表**（`data/element_chart.json`）建好但 v1 不啟用，v1.5 才套用。

## 各資料檔來源

| 檔案 | 來源 |
|---|---|
| `data/monsters.json` | 名冊 = ludens 魔物出沒地點頁；數值 = `monster_stats.baseline()` + 手調 |
| `data/mvps.json` | 名冊 = ludens MVP 圖鑑頁；數值 = `baseline(level,"boss")` |
| `data/maps.json` | ludens 的區域劃分（普隆德拉野外-XXX / 夢羅克野外-XXX） |
| `data/cards.json` | 卡名 = ludens 卡片圖鑑頁；效果 = 自訂經典風格 |
| `data/element_chart.json` | iRO wiki「Elemental Chart (Pre-Renewal)」Lv1 欄 |
| `data/jobs.json` / `data/skills.json` | 經典 Pre-Renewal RO 職業樹與代表技能 |
| `data/equipment.json` | 經典 RO 裝備名 + 自訂數值 |
| `data/items.json` | 經典 RO 道具名 |

## v1 已知偏離原版之處

- **屬性 / 種族用口袋版的設定**（ludens），跟經典 RO 不完全一致。例：口袋版波利是地屬性，經典是水屬性。以 ludens 為準。
- **MVP-地圖分配為了「一圖一 MVP」約束做了調整**：天使波利（原西門平原）暫掛礦洞、巧克猴（原東門村郊）暫掛西門平原。等 v2 圖多了再回歸。
- **卡片效果全部自訂**，非還原口袋版或經典的實際數值。
- **戰鬥數值全部公式產生**，非任何官方數據。

## v2 擴充流程

新增一張地圖 + 一批怪：

1. 到 ludens 魔物出沒地點頁，抓該區域對應等級帶的怪：名字、等級、系、屬性、體型。
2. 每隻決定 `role`（glass/normal/tank），跑 `baseline(level, role)` 取數值起點，微調後寫進 `data/monsters.json`（**只加 row，不動既有的**）。
3. `base_exp` ≈ `round(2 * level**1.6)`、`job_exp` ≈ `base_exp * 0.5`，tank/boss ×1.3。
4. 掉落表：引用 `data/items.json` / `data/equipment.json` / `data/cards.json` 既有 id，或先把新物品加進去。
5. 地圖加進 `data/maps.json`：`level_range`、`monster_ids`、`unlock_base_level`、`mvp_id`。
6. 有 MVP 就加進 `data/mvps.json`（`baseline(level,"boss")` + `cooldown_hours` + `home_map_id`），MVP 卡加進 `data/cards.json` 並放進該 MVP 的 drops。
7. `uv run python -m server.admin content check` 驗證引用完整性 + `uv run pytest tests/test_data_files_valid.py`。

三轉、副本、寵物的資料 schema 到對應階段再擴充 `shared/content.py`。
