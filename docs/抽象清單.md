# 抽象清單

「數值與結果高還原，模擬過程可抽象」——每個為了省資源／可行性而偏離原版模擬方式的點，記在這裡。每項標：原版怎樣 / 我們怎麼近似 / 為什麼。

---

## 戰鬥引擎（第 3 階段）

### #1 ASPD → 每回合攻擊次數

- **原版**：ASPD 決定攻擊間隔，即時逐刀揮砍。刺客 ASPD 190 表示每秒攻擊多次。
- **我們**：回合制批次結算。`attacks_this_round(aspd) = aspd // 100 + (機率 (aspd % 100)/100 的一次額外攻擊)`。ASPD 100 = 每回合 1 刀，ASPD 190 = 每回合 1~2 刀（平均 1.9）。
- **為什麼**：掛機批次模擬跑幾千場，逐刀時間軸模擬太貴。DPS 期望值一致，只是不畫每一刀。

### #2 aoe 技能 v1 當單體

- **原版**：範圍技能一次打多隻。
- **我們**：v1 戰鬥固定 1v1（設計文件），`aoe` 型 effect 在 `skills.py` 走 `_physical_skill` 當單體。
- **為什麼**：v1 掛機是一隻一隻打，沒有多目標場景。多目標留 v2 副本。

### #3 buff/debuff 持續時間 → 回合數

- **原版**：技能效果持續 N 秒。
- **我們**：固定「1 回合 ≈ 2 秒」，`duration_rounds = round(duration_s / 2)`。
- **為什麼**：回合沒有固定時長，取一個代表值。掛機戰鬥多半幾回合內結束，誤差影響小。

### #4 行動順序

- **原版**：ASPD 高者攻擊更頻繁，時間軸交錯。
- **我們**：每回合雙方各行動一次，ASPD 高者該回合先手。ASPD 只額外影響「普攻次數」（#1），不影響「回合內行動幾次」。
- **為什麼**：回合制的行動節奏統一，ASPD 的優勢透過先手 + 多段普攻體現，夠了。

### #5 戰鬥回合上限 500 → 判定 stalemate

- **原版**：戰鬥打到一方倒下。
- **我們**：超過 500 回合雙方都活著 → `outcome="stalemate"`，掛機時視為「玩家打不動這隻怪」→ 撤退。
- **為什麼**：防呆。500 回合打不死代表數值差太多，掛機該換地圖。

### #6 SP 不在連續戰鬥間回復

- **原版**：走路、待機時 SP 緩慢回復。
- **我們**：`simulate_grind` 連續打 N 場，SP 只在戰鬥中消耗、場間不回。
- **為什麼**：戰鬥引擎不碰時間。SP 場間回復是「經過多少時間」的函數，屬第 4 階段（掛機結算器）——結算器按 elapsed time 在每場之間補 SP。**戰鬥引擎階段的 grind 是「不休息連打」的下限情境**，實際掛機會更好。

## 掛機結算器（第 4 階段）

### #7 補品只在場間嗑，不在場中

- **原版**：血條隨時可嗑補品。
- **我們**：一場戰鬥打完、下一場開打前才判斷要不要補（血低於門檻 + 有補品）。場中不補。
- **為什麼**：戰鬥引擎是回合批次，插入場中補品邏輯複雜度大增。v1 戰鬥短（多半 <15 回合），場間補夠用。若單場會被秒，那本來就代表打不過該撤退。

### #8 離線走統計投影，不逐場模擬

- **原版**：不適用（原版沒有離線結算）。
- **我們**：離線 8 小時可能上萬場，不逐場跑。用 20 場樣本估「平均回合/受傷/勝率」，再投影總擊殺、經驗、Zeny（統計），稀有掉落用二項分布取樣 + 保底。在線短時段才逐場模擬。
- **為什麼**：省 CPU。在線／離線期望值有測試校準（比值 ≈ 離線效率 0.6）。

### #9 一場戰鬥固定佔用 `round_seconds × 回合數 + rest_seconds`

- **原版**：戰鬥時長由 ASPD、技能前搖等決定。
- **我們**：`time_per_kill = avg_rounds × 2 秒 + 3 秒`（跑去下一隻的時間）。
- **為什麼**：回合沒有固定時長，取代表值把「回合數」換成「秒數」才能跟掛機時間掛鉤。

### #10 勝率 < 1 用幾何分布估陣亡時機

- **原版**：不適用。
- **我們**：統計路徑若樣本勝率 < 1，用 `win_rate / (1 - win_rate)` 估「平均幾場後輸一場（= 陣亡）」，到那個場數就撤退。
- **為什麼**：統計投影不能把「70% 勝率」當成「throughput ×0.7」——輸一場就是死一次。

### #11 補品用量 = 總傷害扣掉初始血量緩衝

- **原版**：不適用。
- **我們**：統計路徑 `potions_used = ceil((擊殺數 × 每場受傷 - (現在血量 - 門檻血量)) / 每瓶回血)`。
- **為什麼**：短時段一開始滿血，掉到門檻前不用補；長時段這個緩衝可忽略，退化成「每場淨損都要補回來」的穩態消耗。

## 養成（第 5 階段）

### #12 衍生數值用簡化 Pre-Renewal 公式，非查表

- **原版**：HP/SP 是職業 × 等級的查表，ATK/MATK 有多個來源分層。
- **我們**：`build_player_combatant` 用公式：
  - `max_hp = (40 + 等級 × job.hp_per_level × (1.5 + 等級/12)) × (1 + VIT/60)`
  - `atk = (STR + (STR//10)² + DEX//5 + LUK//5 + 裝備) × (1 + 等級/50)`
  - 其餘見 `docs/superpowers/plans/2026-09-06-05-progression.md` §2
- **為什麼**：查表要維護一堆數字，公式一條線好調。加了 `× (1 + 等級/N)` 項讓玩家數值跟得上怪物 HP 的 level² 成長。

### #13 ASPD 不算武器延遲

- **原版**：ASPD = 職業基礎 - 武器延遲 + AGI/DEX 修正，武器類型差很多。
- **我們**：`aspd = min(193, 100 + AGI×0.7 + DEX×0.15 + 裝備aspd)`，不分武器類型。
- **為什麼**：v1 武器種類少，延遲表是額外維護成本。

### #14 轉職無任務步驟

- **原版**：轉職要跑一串任務（打怪、跑腿、考試）。
- **我們**：Job Level 達門檻（一轉 10 / 二轉 40）+ 呼叫端點即完成。
- **為什麼**：任務系統是獨立大模組，列 v1.5。門檻把關已經有「達標才解鎖」的感覺。

### #15 自然血量回復

- **原版**：站著/坐著緩慢回 HP/SP。
- **我們**：場間 `hp_regen_frac_per_sec`（預設 0.4%/秒）× `time_per_kill`。打弱怪淨損 ≤ 0 → 無限撐；打同級硬怪淨損 > 0 → 要補品。
- **為什麼**：掛機遊戲標配。設計文件 §8 漏了，補上。

### #16 加點成本用 Pre-Renewal 原式，點數從等級動態算

- 加點成本 `(V//10)+2` 是 Pre-Renewal 原式。
- 但「可用點數」不存 DB（`stat_points`/`skill_points` 欄位變 dead），改用 `STARTER + Σ每級給的 - Σ已花的` 動態算。避免 migration。

## 打寶（第 6 階段）

### #17 卡片非 flat/percent 效果不套用

- **原版**：卡片有屬性抗性、種族增傷、機率觸發（偷竊、中毒、擊暈）等效果。
- **我們**：`build_player_combatant` 只套 `flat_stat` / `percent_stat`。`element_resist` / `race_damage` / `on_hit_proc` 型效果戰鬥引擎 v1 直接略過（資料照留，戰鬥引擎支援後再啟用）。
- **為什麼**：抗性與增傷要屬性相剋表、proc 要普攻鉤子，都是戰鬥引擎 v1.5 的工作。

### #18 精煉加成用固定 per-level 表

- **原版**：精煉加成隨等級遞增（overupgrade 曲線），且武器精煉加成分武器等級級距。
- **我們**：`REFINE_BONUS_PER_LEVEL` 固定表（atk/matk +2、def/mdef/hit/flee/crit +1、max_hp +15），每 +1 線性疊加，不分裝備等級。成功率／失敗降級照設計文件表。
- **為什麼**：原版曲線要維護武器等級表與 refine 級距，v1 裝備少，線性表夠用且好懂。

## 經濟（第 7 階段）

### #19 v1 無背包/倉庫格數上限

- **原版**：背包有重量、倉庫有格數，要花錢/道具擴充。
- **我們**：v1 不限。
- **為什麼**：friends-scale 無濫用風險。格數上限 + Zeny 擴充列之後。

### #20 賣裝備不計精煉/卡加價，卡片不可賣

- 賣 +7 有卡的裝備跟 +0 空裝同價（`EquipmentDef.npc_sell`）。
- 背包裡的卡片目前無法賣給 NPC（`_content.items` 查不到卡 id）。
- **為什麼**：v1 簡化。玩家寄賣（賣給其他玩家）是 v2 交易所的事。

### #21 MVP 中途逃是「回合開頭血線判定」，非玩家即時操作

- `flee_hp_frac`（預設 15%）在每回合開始檢查玩家 HP，低於門檻就判定撤退，進 1 小時短冷卻、不扣經驗。
- **為什麼**：文字掛機遊戲沒有即時輸入，逃跑必須是預設策略而非手動反應。玩家挑戰前設血線，等同「打不贏就跑」的委託單。

### #22 MVP 掉落用挑戰加成倍率（drop_rate × 3）

- 挑戰成功時，MVP 掉落表的每項機率乘 `mvp_drop_multiplier`（3.0，上限 1.0）。MVP 卡 0.03 → 0.09，單次挑戰約 9%。
- 贏的經驗/Zeny 直接用 `mvp.base_exp`/`job_exp` 與 `zeny_per_kill × 5`。
- **為什麼**：MVP 冷卻 6~24h，一天最多挑幾次，掉落率要夠高才有意義；×3 讓認真養的玩家幾天內能拿到卡。

## 社交（第 9 階段）

### #23 交易物品「放上桌」不即時扣背包，成交才原子互換

- **原版**：交易視窗把物品鎖住，離開背包可用範圍。
- **我們**：`put` 只在 `trade_items` 記一筆，背包數量不動；雙方都 `confirm` 時在單一 transaction 內重驗雙方桌上物品都還在背包 → 一次扣雙方、加雙方、轉移裝備 owner、status=done。任一驗證失敗整筆 rollback、confirm 歸零、status 回 open。任一方 `put` 改桌 → 雙方 confirm 作廢（防抽換）。
- **為什麼**：不即時扣避免「放了又拿走」要回滾背包的複雜度；原子互換保證不會單邊到帳。friends-scale 無高併發搶同一疊物品的壓力。

### #24 聊天用輪詢，非推播

- **原版**：即時推送。
- **我們**：`chat_messages` 表 + client 每 3 秒 `GET /api/chat?channel=&after=<last_id>`。主畫面閒置不撈（避免洗版），`chat` 指令進聊天模式才輪詢 world（+ 公會頻道）。
- **為什麼**：WebSocket 是網頁版才做的事，CLI + REST 輪詢對 friends-scale 足夠，延遲 ≤3 秒可接受。


## v1.5 第 1 波（屬性 / proc）

### #25 屬性相剋 / 抗性 / 種族加傷

- **原版**：完整屬性表 + 武器附屬性 + 護石。
- **我們**：`server/combat/elements.py` 快取 `element_chart`，傷害公式 `physical_damage`/`magic_damage` 收 `element_multiplier` + `resist_pct` + `race_pct`。攻擊屬性 = 技能 element（有的話）否則角色 `attack_element`（武器屬性，附魔卡覆蓋）。抗性/種族加傷從已鑲卡片聚合進 `Combatant.element_resist` / `race_bonus`。傷害 = base × 相剋倍率 × (1+種族%) × (1−抗性%)。
- **為什麼**：加一層乘算，不動既有傷害骨架。武器屬性只做「一把武器一種屬性」，不做左右手 / 多屬性疊加。

### #26 proc 型技能

- **二段攻擊 / 鷹眼連擊（extra_hit）**：被動，`Combatant.procs["extra_hit"]` = 學習等級的機率。普攻命中後 roll，中了追加一擊（不會無限連）。
- **偷竊（steal_loot）**：改成被動 proc（原本是主動、會被 AI 空放）。命中 roll，一場最多算一次成功。settlement 該場額外給 `zeny_per_kill × 0.5` 的 Zeny。
- **致命毒擊（envenom debuff:poison）**：`physical_hit` 命中後掛一個 `Status(kind="dot")`，每回合扣 `max_hp × 1.5% + 技能等級 × 3`，持續 4 回合。
- **為什麼**：proc 掛在 `_one_hit`（單擊）鉤子上，不重寫戰鬥迴圈。DoT 沿用既有 `tick_statuses`。

### #27 技能前置條件

- **原版**：技能樹前置（點 A 到 N 級才能點 B）。
- **我們**：`SkillDef.requires = {skill_id: level}`。`can_learn` 檢查 `current_learned`（含轉職保留的前職技能）。載入器驗證 `requires` key 在本職或前職鏈上。
- **為什麼**：資料驅動，UI 只反映後端判斷。

### #28 DB migration

- `db/connection.py` `_MIGRATIONS = [(version, fn)]`。`init_db()` 跑完 `schema.sql` 後套用未記錄的 migration，記進 `schema_migrations`。一次 `init_db` 內所有 migration 共用一個連線/交易（全套成功才 commit）。
- **為什麼**：上線後不能再砍 `rotxt.db`。friends-scale 不需要 per-migration 交易或 down migration。

- 圖鑑收集加成：v1.5 第 2 波。
